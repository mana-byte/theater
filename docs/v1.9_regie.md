# v1.9 — The régie reads at a glance

A UI change to the régie's participant tree, and the one structural fix that
change requires.

The tree today is a column layout: eight fields per agent, one row each, aligned
so they can be scanned vertically. That is the right shape for `theater ls`,
which is what it grew out of, and the wrong shape for a 52-column sidebar next
to a live agent. Two of those eight fields are the ones a human actually wants —
*which agent, and is it waiting for me* — and they are the two hardest to find,
because status is a word in the middle of a row and the harness is a name in a
clipped 11-column field.

So the leaf becomes a block of three rows with one job: make WORKING and
AWAITING_INPUT unmissable, and put the directory somewhere it can be read
without shearing every other column.

Modelled on opencode's TUI, which is the reference for the style. Not on its
implementation: opencode is TypeScript on OpenTUI, and the mechanism used here
comes from `mistral-vibe`, which is Textual 8.2.8 — the same version this tree
already depends on.

## Ground truth at 7f8aaf1

```
theater/regie/tree.py     render_tree() -> list[(Text, dict)], one entry per participant
                          _node_label() builds a Rich Text: rails, tier+reach marks,
                          harness icon, harness name, status word, short id, cwd
                          _STATUS_COLOR is four hardcoded Rich colour names
theater/regie/app.py      TreePanel.watch_lines() does remove_children() then mount(),
                          one Label per entry, CSS height: 1
                          cursor: reactive[int] indexes that flat list
                          apply_cursor() walks self.children by the same index
                          sidebar width 52, written twice: CSS and resize_pane()
                          tree refresh 1.0s, bus 0.4s
theater/regie/bus_view.py already themed: kind -> theme slot -> App.theme_variables,
                          with _FALLBACK for callers that have no running app
theater/formatting.py     tilde(), short_id(), clip_harness(), tier_mark(), reach_mark()
                          shared with theater/cli.py, deliberately free of rich/textual
theater/harness           icons: claude ✻  codex ◉  opencode ◇  vibe ▤  unknown ?
theater/models.py         Status = idle | working | awaiting_input | dead
```

Three consequences of that shape drive everything below.

**The panel is destroyed once per second.** `watch_lines` calls
`remove_children()` and mounts a fresh `Label` for every row on every tree
refresh. Nothing per-widget survives a tick: not a hover class, not a scroll
offset that `scroll_to_cursor` does not restore, and — decisively — not an
animation timer. Any spinner built on top of the current panel would reset to
frame 0 every second.

**The cursor is a position, not an identity.** When an agent above the cursor
dies, every row below it shifts up and the cursor lands on a different agent.
`x` then kills whoever it landed on. The 1 Hz rebuild does not cause this; it
just re-clamps and moves on.

**`tree.py` is the last un-themed surface in the régie.** `bus_view` resolves
colour through theme slots; the tree still writes `"green"`.

## Decisions

Every one of these had a live alternative. They are recorded with it, because
the alternative is usually the obvious choice and the reason it loses is not.

### The leaf is three rows and one widget

```
                                  ← blank
├── ⣾ opencode  1a2b3c4d          ← status glyph, harness name, short id
│   ~/…/tui_cli_orchestration     ← cwd, dim
```

Rails are carried on both content rows. A tree whose rails work on every other
line is not a tree; the width that costs is bought back by `shorten_path`.

The blank row leads rather than trails, and is part of the leaf's own `Content`
rather than a CSS margin. A margin would render identically, but a leading blank
inside the block means the first leaf gets breathing room under the panel border
for free, and the row cannot be landed on by a cursor or miscounted by a test.

**One widget per participant, not three.** The cursor is an index resolved
against a list of rows; three widgets per agent would make every index mean
"line" instead of "agent" — `j` would stop on a directory — and `apply_cursor`
walks `self.children` by that same index. One widget also means the highlight
spans all three rows with no extra work, and the whole block is one mouse target.

### What the leaf drops

`tier_mark` (S/A/E) is gone. The rails already say who spawned whom, and the
harness name says what it is; the letter was a third encoding of the same two
facts.

`reach_mark` (`*`, not addressable) survives, because it is a different fact and
an operational one: it is *why* `send` fails against a participant. It moves
from a glyph to a style — an unaddressable agent's id renders dim-italic. Same
information, zero columns, and a reader who does not know the convention still
gets the right impression from a greyed-out row.

The status *word* is gone: the glyph is the status. The harness *glyph* is gone
from its own field, because it is now the IDLE status glyph — which is the whole
point of the design.

### Status is a glyph, resolved against the theme

| Status | Glyph | Slot |
|---|---|---|
| `idle` | the harness's own icon (✻ ◉ ◇ ▤) | `$text-muted` |
| `working` | braille spinner, 10 frames | `$primary` |
| `awaiting_input` | `!` bold | `$warning` |
| `dead` | `✗` | `$error` |
| unmanaged pane | `?` | `$text-muted` |

`idle` goes grey rather than staying green. With ten agents in the sidebar the
design goal is that the one wanting attention is the only coloured thing on
screen; a green resting state defeats it by colouring nine rows.

`awaiting_input` takes `$warning` rather than the `$accent` its old magenta maps
to, because it is the one state that means *a human must act*, which is what the
slot is for.

`!` rather than `⚠`. U+26A0 is East-Asian-Ambiguous and many terminals render it
double-wide with an implicit VS16, which would shift the harness name one column
right on exactly the rows being scanned for. A bare bold `!` in a column where
every other row holds a glyph reads unmistakably, and its width is not a matter
of opinion.

An unmanaged pane gets `?` rather than borrowing IDLE. Nobody is observing it,
so "not observed" is an honest answer and "idle" is a guess.

### Rendering moves from Rich `Text` to Textual `Content`

`bus_view` resolves the theme by hand — role, slot, `App.theme_variables`,
`_FALLBACK` — because a `RichLog` holds Rich `Text`, which the stylesheet never
touches, so `$accent` would be a literal Rich rejects.

A leaf is not a RichLog. `textual.content.Content` resolves `$primary` natively
in its style strings, which is why `mistral-vibe` uses `Content.assemble`
throughout. Threading `theme_variables` through a function called on every frame
of a 10 fps spinner is plumbing worth avoiding, and it re-derives what the
stylesheet already knows.

`tree.py` therefore gains a `textual` import. The rich-free rule that protects
`formatting.py` does not apply: `theater/regie/` is TUI-only by construction.
`bus_view` is left alone — migrating it is a separate change with no visible
effect.

Verified before committing to it: `str(Content)` returns plain text, so the
fourteen existing assertions of the form `"vibe" in str(label)` survive. Note
that `Content.append` returns a new object rather than mutating, so `_node_label`
is rewritten as a single `Content.assemble` rather than ported line by line.

### The panel reconciles instead of rebuilding

`remove_children()` + `mount()` becomes: match existing leaves against the new
row list by key, update in place, mount what is new, unmount what is gone.

This is the prerequisite for everything animated, hoverable or clickable, and it
is worth landing on its own — a bisect should be able to tell "the tree looks
different" from "the tree stopped updating".

Keys are namespaced, because not every row is a participant:

| Row | Key |
|---|---|
| participant | `("p", id)` |
| unmanaged pane | `("u", pane)` |
| `── unmanaged ──` separator | `("sep", "unmanaged")` |

`render_tree` returns the key as a third tuple element. The separator currently
has no identity at all — it is recognised by having an empty dict — and a pane id
and a participant id would otherwise share a namespace.

### The spinner owns its own timer

`self.set_interval(0.1, tick)` on the leaf, and `update(..., layout=False)` on
the frame. `layout=False` skips the arrange pass, which is only sound because
every frame has the same cell width; vibe's changelog records adding it to kill
lag spikes.

The alternative was an app-owned frame counter passed into `render_tree(...,
frame=n)`, keeping the function pure and the 1 Hz rebuild untouched. It loses
because reconciliation is wanted anyway for hover and click, and once it exists
the per-widget timer is strictly less machinery than a frame-plumbing API.

Frames are vibe's exact ten, `⠋⠙⠹⠸⠼⠴⠦⠧⠇⠏`, at 0.1s. Braille U+28xx is
unambiguously narrow in every terminal, unlike the harness icons; and there is no
reason for two Mistral tools in the same terminal to spin differently.

A leaf only runs a timer while it is WORKING, and stops it on unmount. An idle
régie costs no frames.

### The cursor becomes an id

`cursor_id: reactive[str | None]`, with the index derived at render time and
`j`/`k` stepping by resolving position. When the agent under the cursor dies, the
cursor falls back to the nearest surviving row rather than silently inheriting
whoever slid into that index.

Nearly free once rows are keyed, and it closes a real footgun: `x` can no longer
kill an agent that scrolled under the cursor between the keypress and the
refresh.

### Mouse

Left click moves the cursor and stages the selected agent. Right click moves the
cursor and toggles its trajectory. Later clicks in a multi-click chain are ignored
so a double click cannot immediately undo the first click.

All three rows of a leaf are one target, which follows from the leaf being one
widget.

Hover is a CSS rule, `$boost`, deliberately weaker than the cursor's
`$accent 20%` + bold so that it stays obvious which row `Enter` will act on.
Hover works today only in the sense that it is repainted away once a second;
reconciliation is what makes it stick.

### Paths shorten in the régie, not upstream

`shorten_path(path, keep=2)` keeps the last two segments and elides the rest:
`~/a/b/c` → `~/…/b/c`, `/var/a/b/c` → `…/b/c`. Applied after `tilde()`, so `~`
is a preserved prefix rather than a counted segment.

It lives in the régie. The daemon should not decide how long a path looks, and
neither should a harness plugin — it is presentation, and the only surface with a
width constraint is the sidebar. `theater ls` keeps full paths: a terminal you
can scroll is not a 60-column panel.

### Configuration

```toml
[regie]
cwd_segments = 2    # min 1
sidebar_width = 60  # min 40
```

`cwd_segments = 0` is rejected: a leaf with no directory at all is a different
feature, not a threshold value.

`sidebar_width` has a floor of 40, below which depth-3 rails plus a two-segment
path no longer fit and the feature the width exists to serve is already broken.
No ceiling — a 300-column monitor may legitimately want half of it, and tmux
refuses anything the window cannot honour.

It is read once and used twice: the `#sidebar` style and `resize_pane`. `App.CSS`
is a class attribute parsed once, so the width is applied imperatively at mount
rather than interpolated into the stylesheet. The two call sites must agree or
Textual and tmux disagree about where the sidebar ends.

Both keys must be written into `config.example.toml` with their defaults, or
`tests/test_example_config.py` fails — by design.

## Commits

Ordering is load-bearing: the leaf's timer cannot survive a panel that rebuilds
itself, so reconciliation lands first.

1. **reconcile the tree panel by key** — pure refactor, no visible change. Own
   test file.
2. **`shorten_path` + `[regie] cwd_segments`** — pure function, config, example.
3. **`AgentLeaf`** — three-row layout, themed status glyphs, spinner. The visible
   change.
4. **mouse** — left-click stage, right-click trajectory, hover.
5. **`[regie] sidebar_width`** — default 60, both call sites.

## Tests

The fourteen in `test_regie_tree.py` survive the shape change: `render_tree`
still returns one entry per participant, so the rail assertions still index
`lines[i]`, and `str()` on `Content` still yields plain text. They are touched
only for the widened tuple.

New coverage, for the three things that have none:

- `test_regie_tree.py` gains `shorten_path` cases — deeper than the threshold,
  exactly at it, shorter than it, home-relative, root — and one status-glyph case
  per state.
- `tests/test_regie_reconcile.py` asserts the property that matters: the same
  ids across a refresh yield *the same widget objects*; a dead agent's leaf is
  unmounted; the cursor id survives a row shift above it.
- `test_regie_app.py` gains click dispatch through the existing pilot —
  `pilot.click` for staging and trajectory toggling, asserting a chained double
  calls `join_pane` exactly once.

The spinner is tested by calling the tick method N times and asserting the frame
index advances and wraps. No test sleeps; vibe's snapshot suite patches the tick
for the same reason.

## Deferred, with rationale

**`bus_view` on `Content`.** It works, it is themed, and a `RichLog` is a
different container with different constraints. No user-visible effect.

**`sidebar_width` as a tmux-side percentage.** A column count is what both
Textual and tmux speak; a percentage would need resolving against a window size
the régie learns asynchronously.

**A status glyph for the harness plugin interface.** Plugins declare a
one-character `icon`, and that is now doing double duty as the IDLE glyph. If a
plugin ever wants to override WORKING or AWAITING_INPUT the interface can grow,
but nothing has asked.
