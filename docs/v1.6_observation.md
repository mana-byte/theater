# v1.6 — Per-plugin observation

## The question, answered honestly

> Why wouldn't making the observer per-plugin — more specialised and accurate on its
> own CLI — improve `await`?

It does improve it. It is not sufficient on its own, and the plan has to say which
half is which, or we will ship better evidence into the same broken consumer and
conclude that per-plugin observation "didn't work".

`await` has five failure modes. Here is what a per-plugin observer does to each:

| # | Failure mode | Per-plugin observer |
|---|---|---|
| 1 | The only wakeup is an in-process `asyncio.Event` (`jobs.py:186`). A second daemon finishing the job never wakes the waiter. | **No effect.** Process-level bug. |
| 2 | `_answer_turn` picks the oldest running job — matching by queue order, not identity (`observer.py:603`). One native message emitting two boundaries consumes two jobs (`claude.py:21-25`). | **Fixes it.** Native turn ids are per-CLI knowledge and nothing else can supply them. |
| 3 | Nothing verifies the prompt arrived. `send-keys` exits 0 and the prompt is silently lost. | **Enables the fix.** The observer is the only thing that can see the user echo land; the reducer has to act on it. |
| 4 | The rescue deadline runs off the observer's quiet clock, not the job's (`observer.py:566`). Effective timeout is 0–60 s depending on the target's history. | **No effect.** Reducer-side. |
| 5 | A job still `running` at timeout is indistinguishable from one that is permanently broken. | **Half.** The plugin can say "I cannot observe this"; the status model has nowhere to put that answer (`models.py:19`). |

So: two of five fixed or enabled by the plugin layer, one half, two untouched. This
plan carries all five, because shipping only the plugin half leaves `await` visibly
flaky and the work looks wasted.

There is also a precondition. Four daemons are currently live against the same
database, which is why every bus event appears three or four times. Any measurement
taken before that is fixed is contaminated. Stage 0 is not optional.

## Where the seam already is

The split this plan wants mostly exists. `theater/harness/source.py` opens with it:

> The observer does two jobs. It *gets* what an agent said, and it *decides* what
> that means. The second job is identical for every harness and is where every
> observation bug in this project has been.

- `HarnessObserver.open_source()` (`observation.py`) is the per-plugin constructor.
- `Source` (`source.py:156`) is the driver interface: `read`, `refresh`, `history`, `aclose`.
- `TranscriptSource` (`source.py:199`) is the free implementation for file-backed harnesses.
- `OpenCodeSource` (`plugins/opencode.py:222`) is already a custom driver over SQLite.
- `Observer` (`observer.py`) is the shared reducer: timers, status policy, bus writes, job completion.

**We are not building four Observers.** We are widening what a driver is allowed to
say and hardening what the single reducer does with it. Four independent reducers
would mean four copies of job completion, and the bug we fix in one would be missing
from the other three.

What the drivers cannot currently express, and must be able to:

- a turn identity, so completion can be idempotent
- a screen reading richer than one boolean (`base.py:313`)
- "I have lost the thread" — driver health, distinct from agent silence
- whether relocating to a different session file is safe for this CLI

## Contract changes

### `Event.turn_id` (`base.py:141`)

Optional native identifier for the turn a boundary closes. Claude has one per
assistant message; codex has `task_started`/`task_complete` pairs; opencode rows have
a message id; vibe has none, so the driver synthesises `f"{attach_generation}:{raw_index}"`,
which is stable for an append-only file.

The reducer completes a job **once per distinct `turn_id`**, deduped in SQLite, not in
a process-local set — with several daemons possible and restarts routine, an in-memory
set is not a dedup key.

### `Attachment.last_event` → `Attachment.snapshot`

`attach_point` parses only the last complete line (`source.py:53`, used at `:301`),
and `Attachment.last_event` carries only the last event of that record (`source.py:87`).
A claude turn that ends with a bookkeeping record therefore attaches as "no boundary
seen" and leaves a job hanging. Note also that `OpenCodeSource`'s attachment never
sets `last_event` at all.

Replace with a driver-supplied snapshot: last boundary seen, current status, current
turn id. A driver that has an authoritative store answers exactly; the file default
scans backwards to the most recent meaningful record instead of taking the last line.

### `ScreenReading` replaces `is_idle_screen` (`base.py:313`)

```
kind: working | prompt | approval | trust | unknown
confidence: low | high
```

`approval` and `trust` are the ones that matter: at an approval prompt, Enter is a
button press, so an injected prompt can auto-approve a tool call. That is the one
false positive with an unrecoverable cost, and a boolean "is it idle" cannot see it.

Keep the current risk asymmetry, but per consumer: `unknown` must never read as
`prompt` for the injection gate, while for the régie's display hint it may.

### `DriverHealth`

`ok | waiting | stale | degraded | unobservable`, plus a counter of unrecognised
records. Today, format drift produces zero events, which is indistinguishable from a
quiet agent — a CLI changing its transcript schema looks exactly like normal progress.

### `HarnessObserver.can_relocate` (default `False`)

`TranscriptSource.refresh()` searches by cwd with `session_id=None` (`source.py:237-252`).
That is correct for vibe, which rotates its session file, and dangerous everywhere
else: two panes in one directory can bind to the same session. Observed — vibe panes
`93380153b5af` and `18acb9a969da` both ended up on session `b3e45798-eb59-7117-dd45-f24efa09f02d`.
Relocation becomes a declared capability, and never rebinds without session identity.

## Reducer changes

### Persistent `TurnAccumulator` — shipped in v1.7 phase E1

`reply` is a local recreated on every `_apply` call (`observer.py:353`). Text arriving
in poll N with the boundary in poll N+1 answers with an empty string, and a
multi-block assistant message keeps only its last block. One accumulator per
participant, living across polls, flushed at each boundary.

Done, along with the turn identity it needed to be worth anything: the accumulator
also remembers which turn ids it has answered, so Claude's duplicate boundary stops
handing a queued second caller the first caller's reply. See
`docs/v1.7_hardening.md` phase E.

### Job-owned deadline

The rescue timer belongs to the job, not to the participant's quiet clock. Each job
gets its own deadline from creation; the observer's quiet clock keeps doing what it
is for, which is status.

### Delivery verification

After `send-keys`, the job stays `pending` until the driver reports the prompt echoed
in the target's input. Only then does it become `running` and start its deadline. The
verification clock must not run while the target is busy — modern CLIs buffer typed
input, so a buffered prompt would otherwise read as `not_delivered`.

This is the fix for the concrete loss we caught: job `a30363a1e13e#43` at 19:20:02.
`send-keys` exited 0 and codex's rollout jumped straight from `task_complete` of `#41`
to `task_started` of `#44` — no `agent.user` event ever appeared, where a working send
produces one within ~50 ms. It was rescued 49.5 s later with an empty result, and the
caller resent the identical prompt as `#44`, which worked in 2.9 s.

### Status model

Split the single enum (`models.py:19`):

- lifecycle: `starting | running | dead`
- activity: `idle | working | unknown`
- attention: `none | input | approval | trust`
- health: as above

Each carries evidence source, confidence and `observed_at`. The régie renders the
composite; the injection gate reads attention and health only.

### Watcher restart

A watcher that dies is retired permanently (`observer.py:189-193`). Restart with
bounded exponential backoff, and surface `degraded` while it is down rather than
letting the participant look normally idle.

## Stages

Each stage is independently shippable and independently testable.

**0. Daemon singleton.** `flock(LOCK_EX|LOCK_NB)` on `~/.theater/daemon.lock`, held for
process lifetime. Never unlink a socket or pidfile we no longer own — compare `st_ino`
recorded at bind (`server.py:224-227` unlinks unconditionally, which deletes a newer
daemon's socket; `_clear_stale_socket` at `:236-253` probes by path and so cannot see
an orphan). Orphans self-terminate when the inode changes. Kill the three current
orphans first: pids `33985`, `37052`, `73431` — user's call.
*Done when:* one `agent.*` bus row per event.

**1. Turn identity + accumulator.** `Event.turn_id`, per-participant accumulator,
SQLite dedup of completions.
*Done when:* a claude message emitting two boundaries consumes exactly one job, and a
turn whose text and boundary land in different polls answers with its text.

**2. Delivery verification.** Pending→running on echo; job-owned deadline.
*Done when:* a dropped `send-keys` fails fast with `not_delivered` instead of hanging
for the rescue window, and a prompt typed at a busy target still succeeds.

**3. Attachment snapshot + declared relocation.**
*Done when:* attaching to a session that already finished resolves its job, and two
panes in one directory never share a session id.

**4. Screen classifier.** `ScreenReading`, injection gate becomes "human present OR
modal on screen".
*Done when:* an approval prompt blocks injection and an ordinary prompt does not.

**5. Health, unknown, watcher restart.**
*Done when:* an unparseable transcript shows `degraded` rather than `idle`, and a
killed watcher comes back.

**6. Contract tests over the fixture corpus.** One suite run against every driver:
arbitrary batch splitting, duplicate boundaries, completed-before-attach, same-cwd
concurrency, schema drift, watcher recovery.

## Fixtures needed (only you can capture these)

Fixtures, not the CLIs' source, are the durable contract — their source moves, a
captured file does not.

Per harness (vibe, claude, codex, opencode):

- transcript: a plain turn; a multi-block assistant message; a turn with tool calls;
  an aborted turn; a turn ending in a bookkeeping record; a compaction/rewrite;
  two panes in one directory
- `tmux capture-pane -p`: idle, mid-turn, permission prompt, trust dialog
- opencode additionally: the SQLite schema and one session's rows

Codex writes rollout timestamps in **UTC** while your shell is UTC+2. Label fixture
timestamps with their zone.

## Out of scope, and the decision that follows

Deleting `await_sessions` in favour of pure message passing — `theater_reply`, a
daemon-owned reply expectation with a nudge, an exchange budget, and
`send_many(join=true)` so the daemon does fan-out and join — stays parked. It is the
right follow-on, but it should come *after* delivery verification and the unified
per-pane queue, because a reply protocol built on an unverified send inherits the same
silent loss. Revisit once stage 2 has been running for a while.

The per-pane outbound queue (FIFO, TTL, depth cap, visible in the régie) is a
prerequisite for that follow-on and a natural companion to stage 4: once injection
queues behind a modal instead of erroring, a false positive costs a delay rather than
a failure, which is what lets the modal detector be strict.
